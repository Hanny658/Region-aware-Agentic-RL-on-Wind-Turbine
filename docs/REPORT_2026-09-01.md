## 1. 实验系统（最终形态）

- **机型/仿真**：NREL 5 MW onshore，OpenFAST 4.2.1（conda-forge），ROSCO v2.10.5 打补丁
  （ZMQ 测量 17→22 通道：+测得桨距、原生桨距命令、当前桨距下限、风速估计、最终命令；C 端持久 socket）。
  恒扭矩（`VS_ConstPower=0`，与基线论文一致）、`PS_Mode=1`、控制步长 10 ms。
- **架构**：ROSCO GSPI + 区域残差 Δβ（oracle 规则分区：原生桨距命令 > 当前下限+0.5° 持续 1 s ⇒ R3，1 s 滞回），
  残差经二阶临界阻尼 damper + 安全层（R2 非负、总命令钳制）。1-DOF toy 数字孪生调用同一 `libdiscon.so`。
- **奖励（统一、区域条件化）**：R2 `w_P(P/P_GSPI−1)`；R3 `w_w·exp(−|δω|/0.02)`；载荷项
  `−λ_L·range_inc`（**10 s 滑窗极差增量**，按后端 GSPI 标定）；动作惩罚 (Δβ/0.1)²。
- **评估（fitness F，任何学习器/监督者不可修改）**：相对同风种子 GSPI，
  **最大化塔基前后 DEL 降幅**，约束能量损失 ≤1%、R3 转速 std 不劣于 GSPI；
  分层报告 **strict**（不劣于）/ **tol2**（转速容差 2%，工程等价）/ **degraded**。
- **PPO**：论文 Table II 超参 + **γ=0.998 / GAE-λ=0.98**（关键修正，见 F4）、探索 σ 状态无关、
  观测 running normalization（采样一致性修正）、按 wave（8 episode）更新、护栏
  （违约才回滚到历史最优状态）+ best-checkpoint 选择。
- **监督者**（每 30 episode，评估 S1+S2）：`guard`（固定权重）/ `llm_fork`（LLM 3 候选 + 单 wave
  分叉验证择优，RHyVE 式）/ `random_fork`（同分叉、随机候选）/ `schedule`（回放 LLM 蒸馏课程表）。

## 2. 已核对的核心结论

**F1（主结论，2026-09-10 重述）：区域分工买到的是调速，不是载荷。**
在单一 canonical 风库上重跑（roadmap §21–§22），`spec+guard` 与 `mono` 在**载荷上无法区分**：
13.93±2.29 vs 13.80±2.71（配对 p=0.96），第二组互斥风场 S7–S10 上 12.54±1.44 vs 12.25±3.10（p=0.89）。
区分二者的是它们花掉的约束：**mono 的转速 std 比 spec 高 +0.05，两组风场共 10/10 种子一致**
（配对 t p=0.0202 与 p=0.0066）。
⚠️ **不要再用 tier 计数陈述这条**：旧写法"mono 0/5 strict vs spec 5/5"在 S7–S10 上变成 4/5——
那组风场把**所有**控制器的转速比整体压低约 0.05，而 mono 本来就贴在边界（1.008–1.020），于是翻面。
阈值统计量不稳，配对连续量稳；论文报后者，tier 作为推论。

**F2（区域分工的物理解耦）**：R3 残差只改善调速（std 比 0.88–1.00、MAE 比 0.86–1.00），
对塔基 DEL 贡献 ≈0（r3only-all-winds：−0.04%）；**塔基减载几乎全部来自 R2 的削峰变桨**
（推力↓，代价 0.07–0.68% 能量）。R2 桨距 agent 在塔基目标下有真实职责（"冻结 R2"决定已撤回）；
叶根疲劳 DEL 用集体变桨只能动 ±3–8%（与论文 15 MW 的 0.2% 一致）。

**F3（奖励设计三次迭代，方法学结论）**：m=10 的 DEL 由 130 s 内最大 1–5 个循环决定；
`|M|` 水平惩罚 → 载荷反馈变桨激发挥舞模态（DEL +17…+740%）；`|ΔM|` 增量 → 压高频小波动、λ≥3 失稳；
**10 s 滑窗极差增量**与 DEL 相关 0.83–1.0、训练稳定。λ 可用区间窄（0.3–1 起步），冷启动 λ=3 必崩，
但**学会之后逐步升 λ 可行**（课程效应，最早由 LLM 发现）。

**F4（根因修正，OpenFAST 特有）**：γ=0.99 在 10 ms 步长下（1 s 视界）对 ~3 s 塔架模态短视,
纯调速奖励也会学出激发塔架的快速变桨（转速 std 比恶化至 1.27、桨距行程 39→57°）；
γ=0.998（5 s）修复（0.93）。此前的 OpenFAST 方法排序全部因此作废并重跑。
其余已修的实现要点：观测归一化统计须用采样时刻的版本；分叉/评估端口与工作目录按 run 隔离；
ckpt_last 经常 degraded，**best-checkpoint 选择必不可少**。

**F5（LLM 的作用，2026-09-09 在单一风库上重做后的版本；此前的"打平"结论已撤回）**：
- 旧结论（roadmap §13）"三个监督变体统计打平、监督者是谁不重要"，是把种子**跨两套风库**配对得出的
  （s0–s2 在已退役的机器，s3–s4 在 Mac；见 C1）。在同一套 canonical 风库上重跑并补到 7 个种子后
  （roadmap §21），结论反转：
- **提议者才是决定性的**：`llm_fork` 17.89±2.02（7 seed，6/7 strict）vs `random_fork` 12.36±5.30
  （7 seed，7/7 strict），差 **+5.53±4.64、7/7 种子全为正、配对 t p=0.0196、精确置换 p=0.0156**；
  对 `guard`（13.93±2.29）差 +3.48，p=0.041。
- **分叉验证在均值上不带来任何东西**：单提案 LLM（`--supervisor llm --no_dry_run`）17.92±1.57，
  与 llm_fork 差 −0.52（p=0.76）。"未验证的 LLM 监督有害"这条旧论断**未能复现**——它原本只有
  旧风库上的两个单种子 run 支撑。
- **合规性也不是监督买来的**：`random_fork` 是 tier 最干净的一臂（7/7 strict）却载荷最差；
  合规由护栏 + best-checkpoint 这一层提供，而每一臂都有这一层。
- **机制（roadmap §21b，零算力）**：LLM 的候选**集**在验证之前就是好的（fork F 均值 +4.93 vs
  随机的 −26.2；每组 3 个候选里 2.2 个 strict vs 1.2），采纳的动作幅度大 2.3 倍且从不"原地不动"
  （0% vs 随机的 29%）；整段训练走出一条方向一致的课程（λ_R3 **6.5×**、w_speed **7.1×**、
  Δβ_R3 **0.20×**），而随机搜索七个 run 走完所有旋钮都回到 0.94–1.20×。**验证是提议质量的替代品，
  不与之叠加。**
- 成本：llm_fork 每次训练仅 5 次调用（~24k prompt / 5.7k completion tokens）；单提案 9 次。
- 仍未决：全部 F 都算在同一组 4 个 held-out 风场实现上，而换风库曾让这条对比翻过符号——
  第二组互斥风场（S7–S10）的复评正在跑（`campaign_c_second_heldout.sh`）。

**F6（与基线的关系）**：相对 GSPI 见 F1；与 MPC 的对比**已完成**（roadmap §16：MPC 调速全场
最佳但塔基 DEL −17.6%，所有监督 spec 变体在 F 上帕累托占优，详见 §3 第 2 条；压力工况下差距
进一步拉大，roadmap §17）；
与论文 15 MW 数字不可直接比（机型与目标权重不同：我们载荷优先，调速增益 4–8% vs 论文 23%，
塔基 15% vs 论文 4.5%）。

**F7（toy 数字孪生的边界）**：toy 与 OpenFAST 在 GSPI 行为上高度吻合，适合筛机制/奖励/超参
（本项目三次奖励迭代都在 toy 上完成），但 (a) toy 的 R2"减载"是对 ζ=0.05 挥舞模态的主动阻尼、
不迁移；(b) toy 策略零样本上 OpenFAST 完全失败；(c) toy 里 negative transfer 的表现形式与
OpenFAST 不同（toy: R3 学不动；OpenFAST: 调速被牺牲）。孪生的正确用途是机制验证与 LLM 分叉试跑。

## 3. 各条线的最终处置

1. ~~监督变体分辨（均值）~~ **已完成（night2, 2026-09-01 晚, Mac）**：llm_fork vs random_fork
   在 5 种子下打平（p=0.55），不再追均值差。schedule 后续（roadmap §14）：旧机 JSON 已随旧机
   清理丢失，从 n1_llmfork_s3 重新蒸馏并以 sched2 复验——回放仅在带 guardrail 时稳健，
   此前的低方差（σ=0.4）结论撤回；该线就此关闭。
2. **MPC 基线：已完成（2026-09-03 晚，roadmap §16）**。LPV-MPC（3 状态：转子+塔架一阶 FA，
   Cp/Ct 表逐步线性化，OSQP 2.8 ms/解）held-out：调速全场最佳（std 比 0.912、还多发 0.3% 能量）
   但塔基 DEL **−17.6%**（15 m/s 处 −33…−64%）——复现并放大了基线论文"MPC 赢调速输塔载"的
   定性结论；所有监督 spec 变体在 F 上领先 MPC 30+ 分（帕累托占优）。用户决定（2026-09-03）：对比基线改为 **GSPI + MPC**
   双基线（与基线论文只做方法参照，不做逐数字对比）。实现：`controllers/mpc.py`
   （LPV-MPC 集体变桨：每 0.1 s 在当前工况点用 Cp 表线性化、OSQP 求解、β≥实时 peak-shaving
   floor、调度变量用 ROSCO 风速估计、扭矩走原生 ROSCO）+ `scripts/mpc_baseline.py`
   （与 evaluate.py 同格式输出，直接进 heldout/paper 表）。调参在 S1+S2 上按 F 选优
   （与其它方法同一模型选择准则），held-out S3–S6 报告 F + 论文四指标。
3. ~~R2 扭矩残差~~ **已完成，明确负结果（2026-09-03，roadmap §15）**：全套实现+防护后，
   5 种子 seed-paired 对照 held-out F 4.1±2.9 vs 纯桨距 13.9±2.3（配对 p=0.007）——能量代价
   本就远未触约束（0.26%<1%），省能换不来任何 F；多出的动作维度在 300 episode 预算内稀释
   R2 桨距学习。主线放弃扭矩通道；作为 future work 保留（更长预算/监督课程/能量侧目标）。
   附带产出：act_dim>1 的 rollout reshape bug 修复、WSE 应用扭矩补丁、"oracle 区域标签是
   奖励攻击面"的机制分析（超速套利与动能抽取两个数学上真实的漏洞及其防护）。
4. Route B（Eureka 式奖励代码进化）；学习型 router（MLP/KAN）——未在本仓库范围内展开。
5. 15 MW / IEA-15 monopile 扩展——未在本仓库范围内展开。
6. **鲁棒性压力扫（roadmap §17，纯评估）**：TI14 / TI22@15 / U18@TI8 三类。区域感知 RL 的塔基
   收益随湍流增强（11.6 → 16.3 → 22.2%）且 20/20 strict，MPC 单调恶化（−17.6 → −27.2 → −56.1%）；
   U18（深 R3、分布外）RL 塔基收益归零（−3.5%），与 F2 一致（塔基减载几乎全部来自 R2 削峰）。
   **未决**：该扫是在 blade 目标的 run 上跑的，塔基列是副产品指标，进手稿前须在 tower 目标臂上
   重跑（纯评估约 1 h）。
